## 1. Where the system is genuinely strong

- **Independent review is substantive, not a formality.** Repo-identity resolver history documents real reproduced defects (fork collisions, sibling bare-repo collisions, transport normalization, unrelated-ref instability, ignored non-`origin` remotes, permission errors misclassified as "not a repository").
- **Actor separation: multiple independent perspectives caught what one missed.** Sonnet accepted; another independent review found a daemon route bypassing the intended protection. The repair separated automatic settlement from reviewed acceptance and added a socket-level regression test — reran successfully. "Different reviewers were dispatched" is not equivalent to mechanically enforced coder/grader/breaker separation, though.
- **Concrete objections override a prior ACCEPT.** REMEDIATE draft explicitly supersedes one ACCEPT after two reviewers found substantive gaps. A reproducible counterexample defeating a vote count is the right decision rule.
- **INVALID_CARD sometimes prevents a dishonest fix.** The T03 amendment records the actual contradiction (optional ledger support added, but the real T08 caller never supplied a store) and stopped instead of quietly widening the mission.
- **Some safeguards are concrete and testable:** git baselines, isolated worktrees, whole-tree inspection, separate settlement events, targeted regression tests. Receipts' sandbox direction (disposable containers, read-only mounts, network denial, dropped capabilities) is sound — but containment and evidentiary validity are separate properties; my receipt probes tested validator behavior with Docker mocked, not container containment.

## 2. Where it is weak, based on this session

**1. Haiku checks existence better than system behavior.** Builderd lifecycle: worker reported Haiku verified 9/9 claims; Sol subsequently returned INVALID_CARD including two false grounding claims, concurrent-start races, PID-reuse risk, PID-file atomicity gaps. Environment scoping: Haiku returned PASS with zero stale references; Sol found the card targeted dormant `runner.py`, missed the live `t03_runner.py ← t08_lifecycle.py` path, overlooked dropped environment data, proposed an illegal ledger `actor_kind`. A signature-and-path check is being mistaken for a reachability-and-semantics check. Would not retain unchanged as a mandatory layer.

**2. Integration work keeps stopping one caller short.** After the accepted T03 amendment: `T08LifecycleConfig.plan_store` defaults to `None`; the new test explicitly injects a store; both production `T08LifecycleConfig(...)` construction sites (T09, T10) omit it. The repair proves the injected lifecycle path can write the ledger — not that existing application construction paths enable that ledger.

**3. The practiced workflow and the executable Strong Card system are different things.** Passed all 11 current documents in `docs/plan/strong-cards/` through Builder's actual `parse_strong_card()`. **Zero were ingestible** (missing required title separators, incompatible Touch List headings). This session demonstrates a manually orchestrated card discipline, not successful use of Builder's own end-to-end card pipeline. Receipts is a manually invoked script; its README calls a reviewer checkbox "enforced wiring" while acknowledging there is no freeze-command integration. A checkbox is not enforced wiring.

**4. Failure handling creates avoidable operator work.** Repeated first-fail locks around already-diagnosed dependency failures, requests to clear them, a resolver worker reporting standalone-script verification because pytest itself was locked. Direct policy conflict: mandatory fail-first testing intentionally produces a red result, while the first-fail hook treats a failed pytest invocation as a reason to block subsequent testing. Keep the prohibition on blind retries; remove the requirement to rediscover/reauthorize the same known failure per worktree.

**5. Operational state is fragmented.** Canonical doctrine, branch-only amendments, copied global hooks, session instructions, cards, git history, temp review outputs, task handles are all separate. Verified the installed dispatch guard differs from the canonical copy; both guards silently ignored a simulated `codex exec` dispatch while blocking the corresponding OpenCode dispatch into the primary tree — these hooks do not enforce the same policy across this session's routes. The global delete-guard/trash system is separate, useful safety infrastructure — it does not solve dispatch ownership, evidence provenance, or acceptance.

## 3. Cost: both — but the repeated pattern is structural inefficiency

The second actor-separation review and the dissenting REMEDIATE reviews were justified expenditure. The avoidable expenditure is what happened before those reviews: reviewing unresolved product semantics, paying models to rediscover absent callers/missing parameter propagation, rechecking names while overlooking the actual runtime path, repeatedly diagnosing the same environment failure, manually recovering dispatch state. A review catching a defect is a success for that review; the same preventable defect class repeatedly reaching review is a failure of the upstream process. No reconciled per-card cost ledger exists covering review/retry/waiting/intervention time — cannot honestly calculate money or hours saved.

## 4. Prioritized changes

1. **P0 — Replace manual freeze bookkeeping with one executable admission path.** Unify authoring schema and Builder's ingested schema; admission binds exact card, baseline, gate definitions, policy revision, review evidence. Repair Receipts before connecting it: require valid claim records and resolvable references; distinguish prerequisite claims from defect evidence; check permitted command outcomes and structured dispositions; actually validate forward/reverse searches; issue a machine-readable result bound to inspected content. Remove the separate mandatory Haiku pass once this replacement demonstrably catches its cases.
2. **P0 — Consolidate dispatch ownership and failure classification.** One durable attempt record linking card revision, worktree, native handle, PID/container ID, output location, deadline, final result. Build on existing T03/T04 machinery. Remove repeated manual polling, per-worktree reapproval of identical diagnosed failures, mandatory model judgment for deterministic infrastructure signatures. Limit parallelism to what the tracker can actually reconcile.
3. **P1 — Remove default duplicate general reviews.** Ordinary bounded changes: grounded card → coder → controller-run confirmation → independent BREAK with explicit FIT. Retain two independent adversarial perspectives only for authorization, process lifecycle, persistence/replay, migrations. Cut the habitual Haiku+Sonnet+Sol stack on every small card; give retained reviewers distinct questions.
4. **P1 — Slice by observable outcome, not file count.** Entry point → transformation → persisted effect as the minimum integration unit. "Add optional ledger support" should not be presented as "wire the live lifecycle" until a shipped entry point demonstrably enables it. Merge tiny plumbing cards when separate acceptance leaves an unused interface; split genuinely independent security mechanisms. Enforce stop-and-reground after the second structural redesign.
5. **P1 — Cut repeated instructions and universal overhead.** RULES.md is 2,224 lines before Receipts. Reduce active contract to a short normative core; keep incidents in appendices, harness recipes in adapter docs. Remove universal PB6 "reviewed disposable feasible implementation" as prerequisite for routine cards. Replace mandatory full-suite-twice (worker+controller) with one authoritative controller regression run plus targeted repetition where flakiness warrants it. Reconcile contradictory operational instructions instead of preserving both as active rules.

## 5. Additional dangerous/fragile findings

**1. Receipts accepts evidence-shaped text without sufficient evidence.** The actual script (Docker mocked) returned PASS for: a card containing only `B1` with no claim receipts; "Already wired (R999)" with no R999 record; a required prerequisite explicitly marked FALSE; a search that returned an error after producing partial matching output. A mismatched-output control correctly blocked. Only existing `R<n>` records are replayed; verdicts are not enforced; exit status doesn't determine success; reverse checking requires only a `B<n>` line to exist. Do not credit §27.5's "mechanical enforcement" claim as implemented.

**2. Receipts cleanup can kill another concurrent audit.** `sandbox_cleanup()` finds every running container descended from `sc-receipts-sandbox:1` and force-removes them — no per-invocation ownership filter. My mock recorded a removal request against an unrelated container ID. Use recorded container IDs or a unique invocation label.

**3. Replay lacks a general runtime/output bound.** Allowlist rejects `tail -f` but accepts other nonterminating commands (checked acceptance, not execution). No hard wall-clock deadline or output-byte cap; output redirected into a host temp file, so an endlessly producing command can consume host disk despite the read-only container filesystem.

**4. Ledger "accepted" still does not prove independent acceptance.** In-memory probe: accepted an attempt with a different actor and no judge verdict/proof, then let the original coder overwrite that outcome with `retry` and an arbitrary nonempty verdict — `can_retry()` returned true. Same-actor ACCEPT control correctly failed. The repair works at its narrow boundary; the broader ledger remains caller-trusting.

**5. An asynchronously launched process is recorded as settled.** `_RUNNER_TO_SETTLE_OUTCOME` maps `"launched"` to `"settled"`. Async branch writes settlement immediately after launch; later reaping updates only the process table, not this T12 settlement. Misleading lifecycle state — a tracker cannot safely interpret "settled" as "the worker has finished." Not established as the cause of this session's lost handles, but an independently verified weakness in the machinery meant to make those incidents observable.
